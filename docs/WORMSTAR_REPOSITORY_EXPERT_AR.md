# Wormstar Repository Expert — ذاكرة وشخصية متخصصة حصريًا بالمشروع

هذا مساعد **RAG** مخصص لمستودع GitHub:
[abdulstarzeki001-sketch/Wormstar](https://github.com/abdulstarzeki001-sketch/Wormstar)،
بما فيه ملفات Star Cyber Audit iSH المدمجة.
لا يعني "التعلّم" هنا تعديل أوزان GPT-OSS؛ بل تحديث مصادر المعرفة المفهرسة تلقائيًا عند تغير ملفات GitHub.

## الشخصية والحدود

- **الاسم:** Wormstar Repository Intelligence.
- **اللغة الأساسية:** العربية؛ يجيب باللغة الأخرى بطلب المستخدم.
- **التخصص:** شرح المشروع، بنية Core وSentinel وiSH، مراجعة الكود، خطط التطوير، أخطاء النشر والاختبارات، وتقارير التغييرات.
- **مصدر الحقائق الوحيد:** محتويات النصوص العامة التي استرجعها من المستودع المحدد؛ لا يستخدم ذاكرة المستخدم الشخصية أو مكتبة AI Studio العامة.
- لا ينفذ تعليمات موجودة داخل ملف مسترجع، ولا يدّعي تشغيل أدوات أو فحوص لم ينفذها.
- إذا كان السؤال خارج المشروع أو لا توجد أدلة كافية، يعيد إجابة محددة تفيد بعدم وجود دليل، دون استدعاء GPT-OSS عندما تكون المصادر فارغة.
- تظهر المراجع بروابط GitHub ورقم الملف ومدى الأسطر حيث أمكن.

## البنية الفعلية

```text
GitHub/Wormstar (main, commit SHA)
      |
      | fetch: fixed URL, path allowlist, bounded text size
      v
Cloudflare Worker scheduled sync (كل 15 دقيقة)
      |                         |
      v                         v
D1 repo_file_index         Workers AI BGE-M3
  path, Git SHA, text           |
      |                    Vectorize REPO_VECTORS
D1 repo_fragments             ID + vectors only
      |                         |
      +------ isolated RAG -----+
                  |
           GPT-OSS / Qwen
                  |
         answer + GitHub sources
```

في Supabase المشروع الحالي الذي يحوي سجلات Wormstar،
أُنشئ schema **wormstar_repo** وجدول **file_catalog** لاختصاص فهرس مسارات GitHub وأحجامها وبصماتها.
تم تعبئة أول لقطة للمستودع، وليس هذا مخزنًا للمحادثات أو الأسرار.
الكتابة إليه من Cloudflare **ليست مفعلة تلقائيًا**؛ المرجع الحي للنصوص هو D1.
لا تستخدم جداول `ai-stayl` المختلفة أو ذاكرة مستخدم أخرى.

## قيود الاستيراد

- تتم معرفة جميع المسارات وأحجامها من شجرة commit في GitHub.
- تُقرأ الملفات النصية المسموحة فقط حتى 205KB لكل ملف وتُحفظ كاملة في D1 (إن كانت آمنة).
- ملفات ZIP/PDF/PNG، الأرشيفات الخام، لقطات OneDrive، المسارات الحساسة والملفات ذات رموز دخول فعلية تُسجّل كمعلومات وصفية فقط؛ **لا تستخدم في إجابات النموذج**.
- الملفات الكبيرة تُحفظ كنص في D1 إن كانت ضمن الحد، وقد يحصل بعضها على عينة من 20 مقطعًا دلاليًا موزّعة؛ البحث النصي الكامل في D1 يكمّل المقاطع التي لا تغطيها Vectorize.
- ملفات فوق الحد وأي ملفات خاصة غير منشورة على GitHub لا يستطيع النموذج قراءتها؛ لا توجد ادعاءات بفهرسة معلومات غير موجودة.
- تستغرق فهرسة المستودع كاملًا عدة دفعات مجدولة. راقب حالة `visited / total`، ولا تخلط بين الفهرس الوصفي وبين عدد الملفات النصية المفهرسة.

## نقاط API مع مصادقة المالك

- `GET /api/repo/status`: حالة المزامنة، عدد الملفات والمقاطع، وGit SHA.
- `POST /api/repo/sync`: استيراد دفعة إضافية، مثال `{"maxFiles":4}`؛ لا يتجاوز 16 ملفًا في طلب واحد.
- `POST /api/repo/ask`: `{"message":"اشرح بنية المشروع","engine":"auto","mode":"assistant","reasoningEffort":"medium","history":[]}`؛ النموذج مقصور على المصادر المقترنة بالسؤال.

في الواجهة: **AI Assistant → Repository Expert** مفعّل افتراضيًا.
يمكن إلغاء تفعيله للوصول إلى المحادثة العامة دون مشاركة تاريخ الرسائل بين الوضعين.
المحادثة العامة القديمة تبقى متاحة؛ المشروع لا يحذف إعدادات المالك ولا معلوماته.

## اختبارات النشر والتحقق

- `cloudflare-worker/tests/repository-memory.test.mjs`: منع traversal، حجب بيانات الاعتماد والأرشيف، عزل الـprompt، مصادقة المالك، والتزام Git SHA.
- `wormstar-ui/scripts/test-worker.mjs`: وجود عناصر الواجهة ووكيل الطلبات للـCore.
- Cloudflare Quality Gate تعمل قبل النشر.
- نتائج النموذج الفعلية لم تُقيَّم بعد على مجموعة أسئلة واقعية من جلسة مصادق عليها؛ اختبارات الكود لا تعني ضمان إجابة صحيحة في كل مرة.

# طرفية Wormstar المحلية

تضيف هذه الوحدة طرفية سطرية حقيقية إلى Sentinel، وخادمًا محليًا مستقلًا يعمل على جهاز Linux. الأوامر اليدوية تعمل في حاوية Docker مخصصة، وليس في Cloudflare Worker أو Core. خدمة الطرفية ومفتاحها منفصلان عن مفتاح Wormstar. لا تدعم الواجهة برامج الشاشة الكاملة مثل محررات TUI.

## التشغيل على Kali / Linux

المتطلبات: Python 3.10+، Docker يعمل لحسابك العادي، واتصال لتثبيت المتطلبات وسحب صورة Python عند أول تشغيل.

```bash
cd ~/Wormstar/integrations/wormstar-linux-terminal
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
bash start.sh
```

افتح على **نفس جهاز Linux** العنوان `http://127.0.0.1:8000`، وانسخ مفتاح الجلسة الذي يظهر محليًا إلى خانة الطرفية. المفتاح عشوائي ولا يُحفظ داخل الموقع أو المستودع. لا تشاركه. عند إيقاف الخادم ثم تشغيله دون ضبط `TERMINAL_ACCESS_TOKEN` يُنشأ مفتاح جديد.

ينشئ التشغيل حاوية محددة باسم `wormstar-linux-terminal-sandbox`: مستخدم غير root، شبكة معطلة، نظام ملفات أساسي للقراءة فقط، صلاحيات Linux مسقطة، وحدود للذاكرة والمعالج وعدد العمليات. المسار الوحيد المثبت من المضيف هو `integrations/wormstar-linux-terminal/workspace/`. إذا وجد البرنامج حاوية بالاسم نفسه لا تطابق متطلبات العزل، يرفض استخدامها. العزل يقلل المخاطر لكنه لا يضمن منع كل ثغرات Docker أو النواة.

## المساعد المحلي الاختياري

لتفعيل اقتراح خطوة من Ollama المحلي وتنفيذها بعد الضغط على الموافقة، شغّل Ollama واختر نموذجًا متاحًا، ثم شغّل الطرفية هكذا:

```bash
export TERMINAL_CAPABILITIES="health,terminal,plan,execute"
export OLLAMA_MODEL="qwen3:1.7b"
bash start.sh
```

التخطيط يستخدم Ollama على `127.0.0.1:11434` افتراضيًا. تحتاج كل خطوة مقترحة إلى ضغط زر الموافقة في الواجهة؛ تظل الأوامر التي يكتبها المالك يدويًا متاحة داخل الحاوية. الخدمة تسجل نوع الحدث وحالته دون تسجيل الأوامر أو المفاتيح. لا تضع أسرارًا في مجلد `workspace` أو مخرجات الأوامر المرسلة إلى النموذج.

## الربط بواجهة Sentinel المنشورة

الخادم يستمع إلى `127.0.0.1` فقط. للوصول من iPhone أو من واجهة Sentinel على جهاز آخر تحتاج بوابة HTTPS/WSS خاصة موثوقة إلى هذا المنفذ مع مصادقة وتقييد وصول مستقلين. لا تجعل Docker socket أو منفذ Codespaces عامًا. في إعداد الخادم اسمح بعنوان Sentinel الدقيق:

```bash
export WORMSTAR_UI_ORIGINS="https://wormstar-sentinel-preview.abdulstarzeki001.workers.dev"
bash start.sh
```

في إعداد Sentinel Worker اضبط المتغير `TERMINAL_UI_BACKEND_ORIGIN` على أصل بوابتك الخاص مثل `https://terminal.example`، دون مسار. ثم يجب نشر نسخة الواجهة بعد مراجعتها. يسمح CSP بذلك الأصل فقط؛ لا يفتح الاتصال لكل العناوين. احرص على ألا تسجل البوابة ترويسات `Authorization` أو `Sec-WebSocket-Protocol` لأن الأخيرة تحمل مفتاح الجلسة أثناء المصادقة.

في Sentinel افتح **ترمنال Linux**، أدخل أصل البوابة ومفتاح الطرفية، ثم اضغط **اتصال**. يجب تشغيل الحاوية والخدمة والبوابة أولًا؛ رفع كود GitHub وحده لا يشغل جهازك.

## الاختبارات

```bash
python3 -m unittest discover -s integrations/wormstar-linux-terminal/tests -v
npm --prefix wormstar-ui test
```

اختبارات الخدمة تستخدم حاوية وPTY بديلين، ولا تثبت جاهزية Docker أو الشبكة الخاصة على جهاز المالك. بعد تشغيل الخدمة على جهازك اختبر الاتصال وأمرًا بسيطًا مثل `pwd`، ثم تحقّق من أن المجلد المعروض هو `/workspace`.

# طرفية Wormstar السحابية (cloud)

باكند **بديل سحابي** لخدمة الطرفية المحلية الموجودة في المجلد الأب
(`integrations/wormstar-linux-terminal/`). يوفّر **الطرفية التفاعلية** بنفس العقد
الذي تنتظره واجهة Sentinel (`wormstar-ui/terminal.js`)، لكنه يعمل على **منصة
سحابية** مثل Railway بدل جهاز Linux محلي عليه Docker — لمن لا يملك جهاز Linux
(مثل مستخدم iPhone / iPad).

## ما الذي يوفّره وما الذي لا يوفّره

| | المحلي (بايثون) | السحابي (هذا) |
| --- | --- | --- |
| مصادقة بتوكن Bearer | ✅ | ✅ |
| قائمة الأصول المسموحة (CORS + WebSocket) | ✅ | ✅ |
| بوابة الصلاحيات (capabilities) | ✅ | ✅ |
| طرفية تفاعلية عبر `/ws/terminal` | ✅ | ✅ |
| وضع الـ AI ‏(`plan` / `execute`) | ✅ | ❌ **غير موجود عمداً** |
| عزل Docker متداخل (بلا شبكة / قراءة فقط) | ✅ | ❌ |
| شِل غير root | ✅ | ✅ (بلا sudo) |

**لماذا لا يوجد وضع AI هنا؟** لأنه ينفّذ أوامر يقترحها نموذج ويعيد مخرجاتها إليه،
وهذا مقبول فقط داخل الحاوية المعزولة المُتحقَّق منها في الباكند المحلي. الواجهة تعطّل
زرَّي التخطيط والموافقة تلقائياً عند غياب الصلاحيتين. وحتى لو طُلبتا عبر
`TERMINAL_CAPABILITIES` يتجاهلهما هذا الباكند.

## نموذج العزل

المنصات المُدارة لا تمنح Docker متداخلاً، فالحاوية المنشورة هي الحدّ الخارجي.
داخلها الخدمة **مفصولة الصلاحيات**:

- عملية الخادم تعمل كـ root **فقط** لتُطلق كل شِل عبر `setpriv` بمستخدم آخر غير
  مميَّز (`tuser`)، مع مسح المجموعات الإضافية، إسقاط **كل** الـ capabilities،
  وتفعيل `no-new-privileges`.
- لذلك لا يستطيع الشِل قراءة بيئة الخادم (`/proc/<pid>/environ` — حيث التوكن
  ومتغيرات النشر)، ولا استعادة صلاحيات عبر برامج setuid.
- عند الإقلاع يُجري الخادم فحصاً ذاتياً يثبت أن الإسقاط يعمل فعلاً؛ إن فشل
  **يرفض العمل**. وإن شُغِّل بلا root يرفض أيضاً (إلا بـ
  `TERMINAL_ALLOW_SHARED_UID=1` للتطوير المحلي فقط).

> **تحذير أمني:** الشبكة متاحة حسب المنصة، ونظام الملفات قابل للكتابة ومؤقت.
> عامِل الصندوق كأنه غير موثوق ولا تضع أسراراً في `workspace`. التوكن هو
> البوابة الوحيدة — لا تشاركه. أي أمر تكتبه يدوياً يعمل بصلاحيات `tuser`
> داخل الحاوية.

## النشر على Railway

1. مشروع جديد ← **Deploy from GitHub repo** ← مستودع `Wormstar`.
2. في إعدادات الخدمة اضبط **Root Directory** إلى
   `integrations/wormstar-linux-terminal/cloud`.
3. أضف المتغيرات:
   - `TERMINAL_ACCESS_TOKEN` — سلسلة عشوائية URL-safe، ٢٤–٢٥٦ محرفاً:
     `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`
   - `WORMSTAR_UI_ORIGINS` — أصل واجهة Sentinel بالضبط (https فقط).
   - `PORT` = `8080`
4. ولّد دومين على المنفذ `8080`.

لا تضف `USER` إلى الـ Dockerfile ولا تشغّل الحاوية بمستخدم غير root: الخادم يحتاج
root لإسقاط صلاحيات الشِل، ويرفض العمل بدون ذلك.

## الربط بواجهة Sentinel

- في Sentinel Worker اضبط `TERMINAL_UI_BACKEND_ORIGIN` على أصل هذه الخدمة
  (مثل `https://xxx.up.railway.app`) ثم انشر الواجهة بعد مراجعتها.
- في الواجهة: **ترمنال Linux** ← أدخل أصل الخدمة ومفتاح الطرفية ← **اتصال**.
  المصادقة بالتوكن، بلا باسورد.

## الاختبارات

```bash
cd integrations/wormstar-linux-terminal/cloud
npm ci
npm test
```

تغطي: المصادقة (توكن مفقود/خاطئ)، الأصل المرفوض، الإعلان عن الصلاحيات المدعومة
فقط، غياب مسارات `plan`/`execute`، رفض مصافحة WebSocket (توكن/أصل)، وجلسة طرفية
فعلية. عند التشغيل كـ root يُختبر أيضاً فصل الصلاحيات حقيقةً: UID مختلف، تعذّر
قراءة بيئة الخادم، `NoNewPrivs=1`، ومجموعة capabilities فارغة (يُتخطّى هذا
الاختبار عند التشغيل بلا root).

# GoClaw مع Wormstar

هذه وصلة اختيارية إلى **GoClaw مستقل**؛ لا تثبّت البوابة أو نموذجاً، ولا تعني أن حاسبة المالك متصلة. تختلف عن تكامل OpenClaw الموجود. الوضع الافتراضي غير متصل، ونجاح اختبار الصحة يثبت استجابة العنوان فقط، ولا يثبت جاهزية الوكيل أو النموذج.

## ما الذي تنقله الوصلة؟

بعد مصادقة المالك واختيار `GoClaw` وإيقاف وضع `Repository Expert`، يرسل Core نص الرسالة وسياق المحادثة المحدود إلى `POST /v1/chat/completions` في البوابة. يُضمَّن السياق السابق كنص مرجعي في آخر رسالة لأن بعض إصدارات GoClaw تعالج رسالة المستخدم الأخيرة فقط. لا يرسل Core تلقائياً مراجع D1 أو ملفات ذاكرة Wormstar، ويرفض طلبات إرفاقها لهذا المحرك. النص الذي يضعه المستخدم بنفسه في الرسالة يُرسل كجزء منها. قد يحفظ GoClaw المحادثة أو يرسلها إلى مزود نموذج، وقد ينفذ أدوات وفق إعدادات وصلاحيات GoClaw على الجهاز المضيف؛ يجب ضبط تلك الصلاحيات في البوابة نفسها.

لا يستدعي Wormstar نموذجاً بديلاً إذا فشلت البوابة. تعرض الواجهة اسم `goclaw:<agent>` وملاحظة أن الصحة لا تثبت جاهزية الوكيل. أذونات التنفيذ الحالية في Core لم تتغير.
نوع المهمة يحدد فحص سياسة Wormstar، بينما تُحدد تعليمات الوكيل والنموذج وعمق التفكير وحدود الرموز والتكلفة من إعداد GoClaw. يجب تطبيق حد إخراج على مضيف GoClaw لا يزيد عن حد سياسة Wormstar، وإعلان القيمة في الإعداد أدناه. يقارن Core الرقم المعلن بالسياسة لكنه لا يستطيع إثبات أن المضيف يطبقه؛ كما أن أدوات GoClaw قد تستدعي النموذج أكثر من مرة، لذا يجب ضبط الإنفاق وعدد استدعاءات الأدوات على المضيف أيضاً.

## الإعداد لاحقاً على جهاز المالك

1. شغّل GoClaw منفصلاً، وهيئ الوكيل والنموذج وراجع صلاحيات أدواته. تعليمات التثبيت وواجهة API في [وثائق GoClaw](https://docs.goclaw.sh/).
2. وفّر وصول HTTPS محمياً بـCloudflare Access إلى البوابة، مع بقاء الخدمة على جهازك مضبوطة بشكل خاص. لا تعرض بوابة غير محمية إلى الإنترنت.
3. اضبط المتغيرات التالية في إعدادات Core على Cloudflare باستخدام آلية الأسرار، **دون وضع قيم حقيقية في GitHub أو المحادثة**:

   | المتغير | المعنى |
   | --- | --- |
   | `GOCLAW_BASE_URL` | أصل HTTPS المحمي، دون مسار أو اسم مستخدم أو معلمات |
   | `GOCLAW_GATEWAY_TOKEN` | رمز بوابة GoClaw |
   | `GOCLAW_ACCESS_CLIENT_ID` | هوية خدمة Cloudflare Access المسموح لها بالوصول |
   | `GOCLAW_ACCESS_CLIENT_SECRET` | سر هوية خدمة Cloudflare Access |
   | `GOCLAW_AGENT_ID` | مفتاح الوكيل في GoClaw؛ الافتراضي `default` |
   | `GOCLAW_DECLARED_MAX_OUTPUT_TOKENS` | حد الإخراج المطبَّق على الوكيل في المضيف، عدد بين 1 و4096 ولا يتجاوز سياسة Wormstar الحالية |
   | `GOCLAW_USER_ID` | اختياري؛ قد يجعل جلسة GoClaw مستمرة حسب إعداد البوابة |

4. بعد النشر المصرح به، سجّل الدخول إلى Sentinel واضغط «فحص GoClaw». إذا استجابت البوابة، اخترها من المحركات، وألغِ اختيار `Repository Expert` قبل إرسال الرسالة. فحص الصحة ليس اختباراً للنموذج؛ جرّب رسالة فعلية للتحقق منه.

يُمسح سياق صفحة Wormstar عند التنقل بين GoClaw والمحركات الأخرى أو تبديل وضع المستودع. قد يحتفظ GoClaw بجلسة أو ذاكرة مستقلة حسب إعداده، ولا يمحوها تبديل المحرك. رمز Wormstar يبقى في ذاكرة الصفحة، ورموز البوابة وAccess تبقى في Core ولا ترجعها واجهة الحالة.

## التحقق

```sh
node --test cloudflare-worker/tests/goclaw-gateway.test.mjs
npm --prefix cloudflare-worker test
npm --prefix wormstar-ui test
```

الاختبارات تستخدم بوابة وهمية؛ الاتصال الحقيقي يتطلب جهازاً وبوابة معدّين واختباراً مصادقاً عليه.

# طرفية Wormstar السحابية (cloud)

هذا باكند **بديل سحابي** لخدمة الطرفية المحلية الموجودة في المجلد الأب
(`integrations/wormstar-linux-terminal/`). يوفّر **نفس العقد** الذي تنتظره واجهة
Sentinel (`wormstar-ui/terminal.js`) تماماً، لكنه مصمَّم ليعمل على **منصة سحابية**
مثل Railway بدل جهاز Linux محلي عليه Docker — وهذا يحل مشكلة من لا يملك جهاز Linux
(مثل مستخدم iPhone / iPad).

## لماذا نسخة ثانية؟

الباكند المحلي (بايثون) ينفّذ كل أمر داخل **حاوية Docker معزولة ومُتحقَّق منها**
(غير root، بلا شبكة، نظام ملفات للقراءة فقط، صلاحيات مسقطة). المنصات المُدارة
لا تمنح عادةً Docker متداخلاً، لذلك **لا يمكن** تشغيل ذلك الباكند عليها كما هو.

هذه النسخة تحافظ على **ضوابط المالك على مستوى التطبيق** وتتنازل فقط عن العزل
المتداخل:

| الضابط | المحلي (بايثون) | السحابي (هذا) |
| --- | --- | --- |
| مصادقة بتوكن Bearer | ✅ | ✅ |
| قائمة الأصول المسموحة (CORS) | ✅ | ✅ |
| بوابة الصلاحيات (capabilities) | ✅ | ✅ |
| قائمة أوامر الـ AI المسموحة (١١ أمراً) | ✅ | ✅ |
| موافقة أحادية الاستخدام مربوطة بالأمر | ✅ | ✅ |
| تنفيذ argv بلا shell + مهلة + حدّ مخرجات | ✅ | ✅ |
| عزل Docker متداخل (بلا شبكة/قراءة فقط) | ✅ | ❌ (الحاوية نفسها هي الحدّ) |
| مستخدم غير root | ✅ | ✅ (بلا sudo) |

> **تحذير أمني:** هنا الحاوية المنشورة نفسها هي حدّ العزل، والشبكة متاحة حسب
> المنصة. عامِل الصندوق كأنه غير موثوق: لا تضع أي أسرار في `workspace` ولا في
> مخرجات الأوامر. التوكن هو البوابة الوحيدة — لا تشاركه، وفعِّل مصادقة إضافية
> على البوابة إن أمكن.

## النشر على Railway

1. من Railway: مشروع جديد ← **Deploy from GitHub repo** ← اختر مستودع `Wormstar`.
2. في إعدادات الخدمة اضبط **Root Directory** إلى:
   `integrations/wormstar-linux-terminal/cloud`
   (حتى يَبني هذا المجلد وحده عبر `Dockerfile`).
3. أضف المتغيرات (Variables):
   - `TERMINAL_ACCESS_TOKEN` — سلسلة عشوائية URL-safe، ٢٤–٢٥٦ محرفاً. ولّدها بـ:
     `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`
   - `WORMSTAR_UI_ORIGINS` — أصل واجهة Sentinel بالضبط (https فقط).
   - `TERMINAL_CAPABILITIES` — `health,terminal` (الافتراضي)، أو
     `health,terminal,plan,execute` لتفعيل وضع الـ AI.
   - (لوضع الـ AI) `OLLAMA_URL` و`OLLAMA_MODEL` لنقطة نموذج يمكن الوصول إليها.
4. ولّد دومين على المنفذ `8080`.

## الربط بواجهة Sentinel

- في Sentinel Worker اضبط `TERMINAL_UI_BACKEND_ORIGIN` على أصل هذه الخدمة
  (مثل `https://xxx.up.railway.app`) ثم انشر نسخة الواجهة بعد مراجعتها.
- في الواجهة: افتح **ترمنال Linux** ← أدخل أصل الخدمة ومفتاح الطرفية
  (`TERMINAL_ACCESS_TOKEN`) ← **اتصال**. المصادقة بالتوكن، بلا باسورد.

## وضع الـ AI (plan / execute)

عند تفعيل `plan,execute` وتوفير نموذج عبر `OLLAMA_URL`:
- النموذج يقترح **أمراً واحداً** من القائمة المسموحة فقط.
- لا شيء يُنفَّذ إلا بعد ضغط **موافقة** في الواجهة؛ الموافقة أحادية الاستخدام
  ومربوطة بالأمر وتنتهي خلال ٥ دقائق.
- تفعيل الـ AI يرسل هدفك ومخرجات الأوامر السابقة إلى النموذج — وجّهه فقط إلى
  نقطة تثق بها.

## الاختبارات

```bash
cd integrations/wormstar-linux-terminal/cloud
npm install
npm test
```

تغطي: المصادقة، الأصل المرفوض، بوابة الصلاحيات، اقتراح plan، ربط الموافقة
وأحادية استخدامها، رفض الأوامر غير المسموحة، وفشل النموذج (مزوّد أعلى المسار).
الاختبارات تستخدم نموذجاً وهمياً ولا تتطلب Ollama حقيقياً.
